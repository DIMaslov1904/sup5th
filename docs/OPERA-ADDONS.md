# Готовность к Opera Add-ons

Сверено 19 октября 2026 с [Acceptance Criteria](https://help.opera.com/en/extensions/acceptance-criteria/) и [Publishing Guidelines](https://help.opera.com/en/extensions/publishing-guidelines/).

Пакет подготовлен к проверке в Opera Desktop, но заявка ещё не отправлена. Открытый репозиторий помогает проверить исходники; решение модерации зависит также от поведения, разрешений и материалов карточки.

## Что подготовлено

- Manifest V3, локально упакованный JavaScript, CSP без внешнего исполняемого кода.
- MIT для проекта; полные уведомления Vue, Punycode и Tailwind включены в ZIP.
- Иконки расширения 16, 19, 32, 38, 48, 64, 128 px. Для карточки используйте [PNG 128 px](../src/assets/icons/icon_128.png); проверьте превью в форме загрузки.
- [Тестовые JSON и пошаговая проверка](TESTING.md) без рабочих таблиц и Google-аккаунта.
- [Описание данных и сетевых действий](PRIVACY.md), короткое описание фоновой работы.
- Яндекс ИКС загружается по «Получить», с пояснением передачи домена. Автоматической загрузки счётчика нет.
- Сборка по тегу, исходники того же тега, lockfile, Node.js и команды воспроизведения в [RELEASING.md](RELEASING.md).
- [Готовые тексты карточки и заметки модератору](OPERA-LISTING.md).

## Перед отправкой

1. **Скриншоты.** Подготовить минимум два содержательных кадра: каталог с демонстрационными проектами и SEO проверяемой страницы. Практичный третий кадр — полный экран SEO/аудита. Для одного кадра показать расположение кнопки расширения в стандартном интерфейсе Opera. Только вымышленные данные, без рабочих адресов и паролей. Opera рекомендует 612×408, максимум 800×600; для popup 520×600 удобнее кадр 800×600. Светлый/белый фон, без лишних расширений и вкладок; PNG без interlace. На 612×408 весь popup 520×600 не помещается — не обрезать основные элементы и не делать текст нечитаемым.
2. **Реальная биометрия Opera.** Вручную проверить включение, блокировку, разблокировку, копирование и автологин с Windows Hello. Моделирование WebAuthn и успешная сборка не заменяют проверку устройства. На macOS проверить PRF/совместимый режим, на Linux — доступный провайдер или корректный отказ. Без этой проверки не заявлять поддержку всех платформ и провайдеров.
3. **Рабочая интеграция.** Проверить авторизацию реального Google Apps Script, один поддерживаемый CMS-вход и support.5th.ru. Для недоступных модератору функций предоставить отдельный безопасный тестовый аккаунт либо согласовать с модератором демонстрацию. Не размещать рабочие доступы в публичном репозитории. Публичные JSON проверяют каталог и копирование, но не настоящий CMS-вход.
4. **Карточка.** Войти в аккаунт разработчика Opera, указать название SUP 5th, категорию Web Development, русский язык, summary и description из [текста](OPERA-LISTING.md). Проверить доступные поля формы: интерфейс кабинета может отличаться от публичной инструкции. Добавить homepage, support/issues, privacy URL, явно выбрать MIT или приложить её текст.
5. **Источник и пакет.** Скачать `sup5th-opera-v<версия>.zip` из конкретного релиза, приложить ссылку на исходники того же тега. GitHub Source code ZIP — исходники, а не установочный пакет. Минифицированная сборка требует доступных исходников и точных команд сборки; публичный репозиторий не отменяет это требование.
6. **Отправка и обновления.** Проверить все поля и загрузить пакет. После одобрения добавить ссылку на страницу Opera Add-ons в README. Следующие версии отправлять через Upgrade того же дополнения. GitHub ZIP не предоставляет нативных автообновлений Opera.

## Разрешения для модератора

| Разрешение | Зачем используется |
| --- | --- |
| HTTP/HTTPS host permissions | Настраиваемые API, иконки, SEO-ресурсы, sitemap и выбранные пользователем сайты для входа. Домены проектов заранее неизвестны. |
| storage | Каталог, настройки, защищённое хранилище и сессионные состояния. |
| offscreen | Обработка DOM и изображений для кеша иконок вне popup в Chromium. |
| webRequest | Получение IP сервера для SEO из ответов сети; ограниченная карта в памяти. |
| downloads | Сохранение изображений из SEO. |
| alarms | Недельное обновление данных. |
| tabs | Определение текущего проекта, открытие и сопровождение вкладки входа/инструментов. |
| scripting, activeTab | Подключение SEO и скрипта заполнения формы к выбранной вкладке. |
| idle | Блокировка защищённых доступов при системном бездействии/блокировке устройства. |

## Что не считать доказанным

- Успешная сборка и проверка API не означают одобрение магазина.
- Единое назначение формулируется как «ассистент сопровождения сайтов»: каталог, доступы, SEO и тикеты относятся к этому процессу. Широкий набор инструментов остаётся предметом оценки one-goal policy; не описывать расширение как набор несвязанных утилит.
- Firefox имеет известное экспериментальное ограничение WebAuthn RP ID. Это отдельная сборка, не предназначенная для Opera; не обещать исправления этой ошибки в описании Opera.
- Магазинная установка создаст собственный ID расширения. Состояние и passkey распакованной установки не переносятся автоматически; проверку биометрии повторить на магазинной версии.

## Техническая проверка

Проверено 19 октября 2026 на опубликованном CI-пакете **4.0.3** в установленной Opera 137 для Windows (Chromium 153), в отдельном тестовом профиле:

- [Build release](https://github.com/DIMaslov1904/sup5th/actions/runs/39251919963) завершился успешно на Linux runner: установка по lockfile, обе сборки, типизация, Firefox-linter, пакеты и метаданные.
- Импорт публичных raw API через полный onboarding: 2 проекта, 3 доступа, 2 сервиса, без ошибок загрузки.
- Popup: `innerWidth = scrollWidth = 520`, горизонтального переполнения нет.
- SEO локальной тестовой страницы: заголовок и отчёт получены, ошибок JavaScript нет.
- Яндекс: 0 запросов до нажатия; после нажатия — только домен и тема без Referer. Смена темы работает; повторное открытие SEO требует нового нажатия. Ответ изображения подменялся в тесте, доступность самого сервиса Яндекса этим не проверялась.
- Иконки имеют заявленные размеры и PNG без interlace; пути manifest существуют, внешних `<script src>` в HTML нет. LICENSE и THIRD-PARTY-NOTICES.txt входят в пакет.
- `npm audit --omit=dev`: 0 известных уязвимостей production-зависимостей на дату проверки. Это не полный аудит безопасности.
- SHA-256 Opera ZIP: `cea630c59a245f85527a459df1fe36e0961a9444d920b18286a40805dd507957`. Chrome и Opera ZIP этого релиза содержат одинаковые байты.

Биометрия реального устройства, Google OAuth/рабочие API, support.5th.ru и поведение браузера на macOS/Linux в этой проверке не выполнялись. Linux runner подтверждает сборку, а не работу UI на Linux. Полный список оставшихся ручных проверок — выше.

Перед каждым выпуском выполнить сборки и проверку типов; проверить размеры и пути manifest/icon, отсутствие внешнего JavaScript, импорт демонстрационных данных, SEO и отсутствие запросов Яндексу до согласия. Popup проверять при ширине 520 px без горизонтального скролла.

Конкретные результаты CI доступны в [Actions](https://github.com/DIMaslov1904/sup5th/actions). Известное предупреждение Firefox-linter про `innerHTML` относится к статическим шаблонам Vue; ошибок linter быть не должно. Это не результат проверки Opera Add-ons.
