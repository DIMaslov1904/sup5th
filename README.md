# SUP 5th

Manifest V3: каталог проектов и доступов, заполнение форм авторизации, SEO страницы, аудит ссылок, объединение sitemap и локальные инструменты.

Исходный код, тестовые данные и релизы хранятся в одном репозитории.

[Скачать сборку](https://github.com/DIMaslov1904/sup5th/releases)

## Установка

| Браузер | Пакет | Установка и обновления |
| --- | --- | --- |
| Chromium: Chrome 130+, Opera, Edge и другие | `sup5th-chromium-v<версия>.zip` | Распаковать и загрузить папку в режиме разработчика через менеджер расширений браузера. Для новой версии заменить файлы в той же папке и нажать «Перезагрузить». |
| Firefox 140+ | Подписанный Mozilla `.xpi` | Установить через `about:addons` → шестерёнка → «Установить дополнение из файла». ZIP без подписи — для отправки Mozilla. |
| Safari 18.4+ на Mac | `sup5th-safari-v<версия>.zip` | Временная неподписанная установка через Safari → Настройки → Разработчик → «Добавить временное расширение». |

Архивы GitHub **Source code** содержат исходники; для установки выбирайте пакет нужного браузера из списка assets релиза. Отдельного пакета Opera нет.

Расширение проверяет GitHub Releases раз в сутки и вручную по кнопке. В **Настройки → Обновления** находятся текущая версия, дата последней проверки и скачивание пакета для текущего браузера. Пока подписанный XPI не добавлен, Firefox показывает ожидание пакета. Установка обновлений выполняется пользователем.

## Запуск

Node.js 24.13.1. Сборка Chromium используется для Chrome и Opera; Firefox и Safari имеют отдельные сборки.

```bash
npm ci
npm run dev
npm run build
npm run build:all
npm run typecheck
```

Для установки распакованной сборки откройте `chrome://extensions`, включите режим разработчика и выберите `dist`.


## Firefox

```bash
npm run dev:firefox
npm run build:firefox
npm run lint:firefox
```

Сборка находится в `dist-firefox`, архив — `release/sup5th-firefox-v<версия>.zip`. Для временной установки в Firefox откройте `about:debugging#/runtime/this-firefox`, нажмите «Загрузить временное дополнение» и выберите `dist-firefox/manifest.json`.

Пакеты публикуются в [Releases этого репозитория](https://github.com/DIMaslov1904/sup5th/releases). После сборки владелец вручную добавляет подписанный XPI к тому же релизу. Встроенная проверка читает список файлов напрямую, без отдельных JSON и workflow метаданных. Пользовательского `update_url` в manifest нет.

Цель первого этапа — Firefox Desktop 140+. Фон работает как непостоянная страница Manifest V3.

Firefox не поддерживает ограничение `storage.local.setAccessLevel`. Поэтому данные, настройки и доступы сохраняются в IndexedDB страниц расширения (`sup5th-private-data`); в `storage.local` записываются только метки изменений для обновления интерфейса. Ключ разблокировки и состояние сессии остаются в доверенном `storage.session`. Content scripts получают данные только через разрешённые сообщения.

Биометрическая защита в Firefox открывается на отдельной странице расширения. Включение и разблокировка требуют нажатия кнопки на этой странице; закрытие popup не прерывает операцию. Копирование, автологин или загрузка доступов продолжаются после успешной разблокировки. Страница привязана к одноразовому запросу и вкладке на пять минут; закрытие вкладки или отмена не разблокируют хранилище. Состояние запроса содержит только ссылки на записи, без паролей и ключей. Для копирования после проверки устройства используется разрешение `clipboardWrite`. Сценарий Firefox пока экспериментальный: выбор RP ID по адресу расширения не проходит реальную проверку браузера (`The operation is insecure`); требуется отдельное исправление с поддерживаемым RP ID. Проверки с имитацией WebAuthn этот запрет не обнаружили. Chrome сохраняет прежний RP ID и сценарий внутри popup.

В Firefox manifest заявлены передача данных авторизации (`authenticationInfo`) при входе и адресов сайтов (`browsingActivity`) при сетевых проверках и загрузке счётчиков/иконок.

## Safari на Mac

```bash
npm run build:safari
```

Папка сборки — `dist-safari`, архив — `release/sup5th-safari-v<версия>.zip`. Xcode, приложение-оболочка и подпись для временной установки не нужны.

1. В Safari → Настройки → Дополнения включите функции для веб-разработчиков.
2. На вкладке «Разработчик» разрешите неподписанные расширения. Safari может запросить системное подтверждение.
3. Нажмите «Добавить временное расширение» и выберите `dist-safari` либо ZIP сборки. В некоторых версиях Safari эта команда находится в меню «Разработка».
4. Включите SUP 5th и разрешите доступ к сайтам, с которыми работаете. Для загрузки данных и ресурсов нужны разрешения также на адреса API и конечные адреса перенаправлений.

Safari удаляет временное расширение через 24 часа или при выходе из браузера. Разрешение на неподписанные расширения тоже сбрасывается при выходе. Это не постоянная установка: после повторного добавления проверяйте настройки и подключение данных; сохранность временного хранилища между удалением и установкой не гарантируется. [Правила временной установки Apple](https://developer.apple.com/documentation/safariservices/running-your-safari-web-extension).

Для обновления замените содержимое папки новой сборкой и перезагрузите временное расширение в настройках Safari. Если оно уже удалено, добавьте папку повторно. Проверка GitHub Releases выбирает только пакет Safari; пакет Chromium вместо него не предлагается.

Отличия Safari:

- Кнопка «Закрепить» скрыта; боковая панель не подключается. SEO в popup и отдельной вкладке остаётся.
- Изображение открывается в новой вкладке кнопкой «Открыть оригинал»; сохранить его можно средствами Safari. API загрузок в Safari нет.
- Данные хранятся в IndexedDB страниц расширения; `storage.local` содержит только метки обновлений. Ключ разблокировки находится в закрытом `storage.session`.
- Прогресс загрузки API также хранится в IndexedDB и не зависит от свободного места в `storage.session`. Временный SEO-кеш учитывает общую квоту и оставляет запас для прочего состояния. При нехватке места удаляются старые SEO-отчёты; ключ защиты и ожидающие входы сохраняются. Ошибка хранилища сама по себе не вызывает предложение Google-авторизации.
- Нет API системного простоя и блокировки экрана. Вместо этого защищённая сессия действует 10 минут после разблокировки, затем требуется новая проверка устройства. Срок проверяется при каждом доступе к ключу, даже если фоновое событие задержалось после сна Mac. Завершение браузерной сессии также удаляет ключ.
- Настройка passkey и разблокировка открываются в отдельной вкладке с одноразовым запросом. Защита включается только после проверки повторного получения секрета и расшифровки. Неподдерживаемый провайдер или отмена не включают защиту и не понижают существующее PRF-хранилище до режима совместимости. При копировании после разблокировки нажмите «Копировать» в этой вкладке.
- Копирование доступов использует отложенное содержимое `ClipboardItem`, чтобы сохранить пользовательский клик во время запроса к фону. Текст пароля не кешируется в карточке заранее.

Проверки кода: `npm test`, `npm run build:all`, `npm run lint:firefox`. Автоматическая проверка в Safari WebDriver требует Safari 26+ и включённой настройки «Разрешить удалённую автоматизацию». Она не заменяет ручную проверку выбранного провайдера Touch ID/passkey и Google-авторизации в обычном профиле Safari.

## Неочевидные функции интерфейса

- Поиск понимает Unicode/Punycode, варианты раскладки и транслитерацию русских букв: например, «мт» находит `mt21`, «щ» — `shch`, «ё» — `yo`. Ссылки сохраняют рабочие URL.
- Вставка в поиск удаляет нецифровые символы и открывает тикет, если осталось 6–8 цифр. В остальных случаях работает обычный поиск. В модальном окне тикета длина номера не ограничена.
- Для `https://support.5th.ru` переход к тикету сохраняется при истёкшей сессии: расширение обрабатывает `login.php?from=...` и `expired.php?from=...`, входит через единственный полный доступ к этому HTTPS-адресу из «Сервисов» и возвращает нужный тикет. При действующей сессии повторного входа нет. Автовход выполняется один раз; при ошибке, нескольких доступах или заблокированном хранилище доступен ручной вход с возвратом к тикету в течение пяти минут в той же вкладке. Пароли в состоянии перехода не сохраняются.
- Открытая карточка «Сайт» обновляется при изменении каталога: название, ссылки и репозиторий соответствуют новым данным; удалённый проект больше не показывается.

## Статус pipeline

Переключатель «Показывать статус pipeline в проекте» по умолчанию выключен. После включения проверяется GitLab badge для `main`, затем для `master`, если в `main` pipeline не найден. Ссылка на коммиты соответствует найденной ветке. При наведении или фокусе рядом со статусом появляется кнопка «Обновить статус pipeline»: она принудительно загружает актуальный badge, сохраняя текущий на время запроса. Если обе ветки возвращают отсутствие pipeline, результат сохраняется локально для репозитория; повторное открытие карточки не делает запросов. Кнопка «Проверить снова» очищает этот результат и повторяет проверку. Сетевые ошибки и запросы авторизации не сохраняются как отсутствие pipeline. SVG и блокировка повторных запросов после требования авторизации живут только до закрытия popup.

## API и формат данных

Адреса Apps Script задаются в настройках. Доступ к Google API проверяет Google; запросы API выполняются с cookies.

Проекты и доступы автоматически обновляются раз в сутки. При запуске браузера и после разблокировки хранилища также проверяется давность данных: каждый источник загружается, если с последней успешной загрузки прошло не менее 24 часов или изменился его URL. Для загрузки защищённых доступов требуется разблокированное хранилище. Ручное обновление доступно в любое время. Прежнее недельное расписание заменяется автоматически при обновлении расширения.

API проектов возвращает массив в `result` (либо корневой массив). Строка проекта:

```json
{
  "result": [
    [
      "название",
      "URL сайта",
      "инструкция",
      "URL админки",
      "CMS",
      "ключ создания тикета",
      "Git"
    ],
    ...
  ]
}
```

API доступов:

```json
{
  "result": {
    "access": [
      [
        "Проект",
        "https://example.org",
        "login",
        "password",
        "ftp.example.org",
        "ftp-user",
        "ftp-password"
      ],
      ...
    ],
    "services": [
      [
        "Сервис",
        "https://service.example.org",
        "login",
        "password"
      ],
      ...
    ]
  }
}
```

Сохранены нормализация пробелов и несколько логинов/паролей в одной ячейке через перевод строки. Позиции логинов и паролей должны совпадать.

В URL сайта у проектов и доступов префикс `!` ограничивает запись только указанным хостом: `!example.org` или `!https://example.org` действуют на `example.org`, но не на `www.example.org` и другие поддомены. Без `!` запись действует и на поддомены. Ограничение относится только к своей записи; проекты и доступы настраиваются независимо. При импорте маркер удаляется из ссылок и сохраняется как отдельный признак. Для нескольких доступов одного хоста на самом хосте доступны все записи, на поддоменах — только записи без `!`; по-прежнему выбирается ближайший подходящий домен. Для применения изменений в таблице обновите соответствующие данные API в расширении.

Расширение присваивает записям локальные UUID.

## Защита доступов

Включается пользователем. Используется passkey/WebAuthn с обязательной проверкой пользователя. На Windows сохранены параметры сценария до адаптации под Mac: платформенный ключ, `residentKey: 'required'`, транспорт `internal` и запрос PRF через `evalByCredential`. Выбор провайдера контролируется браузером и Windows; наличие Windows Hello не гарантирует выдачу PRF. На Windows настройка открывается в отдельной вкладке расширения. После создания ключа пользователь отдельно нажимает «Проверить разблокировку». Только после этого проверяется будущая разблокировка через `get()`, даже если секрет уже получен при `create()`. Защита включается только после успешной проверки: секрет должен возвращаться и совпадать с результатом создания, если он был получен. Существующие PRF-хранилища продолжают использовать прежние ID, соли и метки вывода ключа. На macOS выбор провайдера предоставляется браузеру. Если доступен PRF, ключ шифрования выводится из PRF-секрета. Для iCloud Keychain («Пароли», macOS 15+) в окне создания ключа можно выбрать «Другой способ» → «Связка ключей iCloud». Также доступен Google Password Manager с поддержкой PRF.

При настройке на Mac провайдера без PRF автоматически включается локальный режим совместимости. В нём ключ обёртки выводится через HKDF-SHA-256 из credential ID с отдельной меткой и случайной солью. В расширении сохраняются только SHA-256-хеш идентификатора, соль, имя ключа и зашифрованный ключ хранилища. Сам credential ID не передаётся в background и не записывается в storage. Разблокировка использует discoverable `get()` с пустым `allowCredentials`, проверяет хеш выбранного ключа и флаги UP/UV ответа. Локальная регистрация требует resident key; в имени ключа есть короткий код для выбора среди старых passkey.

Режим совместимости согласован как дополнительный слой защиты: credential ID не имеет гарантий секретности PRF. Собственный сервер, сетевые запросы и отдельное приложение для этого режима не нужны.

На Mac если поддержка PRF подтверждена или ответ не содержит этого признака, секрет сначала запрашивается через отдельный `get()`; отсутствие секрета позволяет выбрать режим совместимости. Для совместимости с Windows Hello сохранён прежний переход `create()` → `get()` без перехода на credential ID.

Пароли и FTP-секреты шифруются AES-GCM. Логины, адреса и признаки наличия доступа остаются открытыми. Разблокированный ключ находится только в `storage.session`.

В Chromium и Firefox автоблокировка срабатывает при 10 минутах без пользовательского ввода на устройстве через `idle`, блокировке экрана и завершении браузерной сессии. Это системная активность, а не активность только popup. В Safari действует отдельный 10-минутный срок после разблокировки, описанный выше. Блокировка аннулирует ожидающий автологин. Ожидающие сессии авторизации содержат ссылки на записи, а не пароли.

`storage.local` и `storage.session` доступны только доверенным страницам расширения. Привилегированные сообщения проверяют отправителя. Content scripts получают только данные для явно начатой операции.

Потеря passkey требует повторного подключения данных. Отключение защиты после разблокировки возвращает локальное открытое хранение паролей.

## Разрешения

Расширение имеет постоянный доступ ко всем HTTP/HTTPS-сайтам через `host_permissions`. Дополнительных запросов разрешения для отдельных доменов нет. Каталог проектов не зашит в manifest.

- SEO подключается программно через `activeTab` после открытия расширения пользователем.
- При автологине скрипт заполняет только вкладку, открытую этой операцией. Если хранилище заблокировано, сначала требуется биометрия.
- Проверка ссылок, загрузка иконок и источников sitemap используют постоянные разрешения на HTTP/HTTPS.
- Доступы можно отозвать в настройках Chrome. Без разрешения сетевая проверка показывает неопределённый результат.

## SEO

При открытии SEO автоматически восстанавливается результат текущего документа либо начинается анализ с preloader. Отчёт привязан к вкладке и документу; после закрытия popup сохраняется на одну минуту в рамках сессии браузера.

Метаданные DOM показываются сразу. HTTP, robots.txt и sitemap догружаются независимо; сохранённая незавершённая проверка продолжается при повторном открытии. IP и цепочка HTTP-ответов снимаются только во время запроса анализируемой страницы; постоянного наблюдения за сетевым трафиком нет. В «HTTP-заголовки и редиректы» показаны исходный адрес, переходы, конечный ответ и X-Robots-Tag. Cookies и заголовки авторизации в отчёт не включаются.

В обзоре первыми идут Title, Description, Keywords, Canonical и Robots; дополнительные метатеги доступны в «Расширенное», затем показаны URL, Base, IP и HTTP. Теги без названия скрыты, Viewport показывается вместе со значением.

Цветом выделены только значения; пояснения открываются при наведении или фокусе. Для Title зелёный диапазон — 30–65 символов, жёлтый — 20–29 и 66–80, красный — пустое значение, менее 20 или более 80. Для Description: зелёный — 70–160, жёлтый — 50–69 и 161–200, красный — пустое значение, менее 50 или более 200. Это редакционные ориентиры, а не ограничения поисковиков: [Google о Title](https://developers.google.com/search/docs/appearance/title-link) и [Description](https://developers.google.com/search/docs/appearance/snippet). Дубли основных тегов и их расположение вне head отмечаются отдельно. HTTP 200 зелёный, редиректы и неизвестный результат жёлтые, 4xx/5xx красные; показан ответ повторного запроса без cookies.

В «Ссылки» доступны проверка и копирование URL. В «Изображения» наведение или фокус на превью показывает увеличенное изображение на шахматной подложке; Escape закрывает подсказку. Яндекс ИКС находится в «Индексация», в блоке «Индекс качества сайта | Вебмастер», и загружается по кнопке «Получить». В «Инструменты» добавлены локальные SVG-иконки категорий сервисов. Кнопка «На весь экран» открывает «SEO страницы» с тем же разделом и исходной вкладкой.

Действия SEO всегда прижаты к низу окна, включая короткие вкладки, и остаются видимыми при прокрутке. Title, Description, Canonical и URL копируются кнопками у соответствующих значений. Успешное копирование подтверждается локально и кратковременно, ошибки закрываются пользователем. Анимации интерфейса учитывают системное уменьшение движения. Метки изображений на странице переиспользуются и обновляют геометрию преимущественно в видимой области.

Кнопка «Закрепить» после «Обновить» открывает боковую панель с тем же интерфейсом, что и отдельная страница расширения: обзор SEO, подробный аудит, sitemap и инструкции. Chrome использует Side Panel API, Firefox — `sidebarAction`. Исходная вкладка и выбранный раздел передаются в панель; адрес исходной страницы виден в её заголовке. Контекст сохраняется отдельно для каждого окна до конца сессии браузера. Переход или перезагрузка исходного сайта обновляет отчёт; закрытая вкладка показывает сообщение вместо устаревших данных.

Объединяются применимые meta robots, показываются ограничения для Googlebot и Yandex. robots.txt сопоставляется с нормализацией Unicode и percent-encoding. Ошибка получения правил даёт неизвестный результат. Отсутствие noindex не гарантирует индексацию.

HTTP-проверки выполняются без cookies. Различаются подтверждённые 404/410, необходимость авторизации, ограничение проверки, ошибка сервера, таймаут и неопределённая сетевая ошибка. Отчёт указывает размер выборки; дубли проверяются только среди полученных метаданных.

Детальный аудит показывает результаты отдельных проверок без общего SEO-процента: подтверждённые факты, проверки с проблемами, рекомендации, неизвестные и неприменимые результаты. Длина метатегов, количество H1 и отсутствие необязательных полей не считаются подтверждёнными техническими ошибками. Для Canonical проверяются количество, расположение в head и корректность URL; доступность и индексируемость его цели здесь не проверяются.

Источник метаданных текущей страницы — снимок DOM с датой. HTTP проверяется отдельным GET без cookies и без кеша; метаданные исходного HTML и DOM сравниваются, а noindex в исходном HTML/HTTP проверяется отдельно от noindex в DOM. Если доступны исходные строки повторных X-Robots-Tag, учитываются их отдельные области действия. Если браузер вернул только объединённую строку и область noindex неоднозначна, результат для затронутых роботов считается неизвестным. Время до получения заголовков показывается как замер запроса и не превращается в оценку скорости сайта.

По умолчанию проверяются 10 адресов, включая текущий URL. Количество можно изменить на странице перед запуском или на паузе, пока HTTP-обход не завершён: от 1 до 500 адресов, не меньше числа уже начатых проверок. В выборку входят только найденные в исходном DOM уникальные внутренние HTTP(S) URL того же протокола, домена и порта; ссылки вложенных страниц не обходятся. Фрагменты удаляются, параметры запроса сохраняются. Совпадения Title и Description считаются отдельно среди полных HTML-ответов HTTP 200 по уникальным конечным URL; PDF, ошибки, обрезанные ответы и несколько редиректов на одну страницу не создают ложные дубли. В отчёте показаны URL каждого совпадения и фактическое покрытие выборки.

Результаты DOM появляются сразу, HTTP-ответы, robots.txt и sitemap обновляются независимо по мере получения. «Пауза» приостанавливает очередь новых запросов, уже отправленные завершаются. «Продолжить» возобновляет ту же проверку без повторения полученных ответов.

Правила robots.txt вычисляются отдельно для Googlebot и Yandex; показано правило, определяющее результат. Ошибка получения, HTML вместо robots.txt или обрезанный файл дают неизвестный результат. Sitemap проверяется по содержимому XML, включая индексы и вложенные карты. Если часть карт не прочитана, отсутствие текущего URL не объявляется доказанным. Остановка сохраняет полученные ответы как неполный отчёт; смена исходного документа во время аудита помечает отчёт как снимок прежней страницы.

Sitemap: вложенные индексы, gzip, объединение и дедупликация. В аудите и «Едином sitemap» показаны повторяющиеся URL, число их вхождений и исходные файлы; счётчик повторов учитывает каждое вхождение сверх первого. «Единый sitemap» также показывает промежуточные результаты и поддерживает паузу/продолжение. Защитные ограничения сетевого анализа: 200 файлов, 50 000 URL, до 8 МБ распакованного текста одного файла. Неполный результат обозначается явно и экспортируется как `sitemap-partial.xml`.

Тяжёлый SEO-отчёт сохраняется при новом сканировании; изменения фильтров и навигации передают небольшой патч состояния с объединением частых обновлений.

## Быстрый доступ к проектам

Быстрый доступ закреплён только в списке проектов. В нём до 7 плиток, равномерно занимающих ширину ряда: сначала избранные, затем последние посещённые проекты без повторов. SVG-сердечко поверх иконки в карточке закрепляет проект независимо от настройки последних: для незакреплённого проекта оно появляется при наведении или фокусе, для избранного видно всегда. Переключатель «Показывать последние проекты» находится в «Настройки → Подключение → Доп. функции» и по умолчанию выключен. Открытие карточки или переход на сайт из быстрого доступа перемещает проект в начало последних: новые слева, после избранных. Хранятся только 7 последних уникальных проектов, без счётчиков и срока давности; прежняя история переносится по времени посещения. Выключение последних очищает историю открытий и сохраняет избранное. Плитка раскрывается после 300 мс наведения, при фокусе с клавиатуры — сразу. Обычный каталог не ограничен и не виртуализирован; изображения логотипов используют lazy loading.

Все три сборки с проверкой типов запускаются командой `npm run build:all`.

## Структура

```text
src/background/
  service-worker.js       события и маршрутизация сообщений
  storageRepository.js    схема, очередь записи, поколение данных
  apiSettings.js          открытые адреса API
  apiRefresh.js           запросы, обновление и фоновые задания
  catalogueData.js        нормализация и индексированный каталог
  recordIdentity.js       локальные UUID
  credentialVault.js      шифрование и системная автоблокировка
  projectAccess.js        доступы и сессии автологина
  actionBadge.js          индикатор проекта
src/content-script/       формы, SEO и интеграция саппорта
src/popup/                интерфейс, фоновые состояния, настройки и инструменты
src/options/              инструкция, подробный аудит и sitemap
src/biometric/            отдельная страница WebAuthn для Firefox, Safari и настройки Windows
src/icons/                IndexedDB, очередь и обработка favicon
src/utils/                адреса, SEO-правила, WebAuthn и генератор паролей
```

Стек: Vue 3, Vite 8, Tailwind CSS 4, CRXJS. Постоянными данными управляет worker; popup подписывается на изменения хранилищ и использует небольшой общий реактивный модуль состояний.
