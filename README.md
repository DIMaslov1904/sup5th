# SUP 5th

Manifest V3: каталог проектов и доступов, заполнение форм авторизации, SEO страницы, аудит ссылок, объединение sitemap и локальные инструменты.

## Запуск

Node.js 24.13.1. Расширение рассчитано на Chrome 130+.

```bash
npm ci
npm run dev
npm run build
npm run typecheck
```

Для установки распакованной сборки откройте `chrome://extensions`, включите режим разработчика и выберите `dist`.


## Firefox

```bash
npm run dev:firefox
npm run build:firefox
npm run lint:firefox
```

Сборка находится в `dist-firefox`, архив — `release/sup5th-firefox-v<версия>.zip`. Для временной установки в Firefox откройте `about:debugging#/runtime/this-firefox`, нажмите «Загрузить временное дополнение» и выберите `dist-firefox/manifest.json`.

Пакеты для установки публикуются отдельно в [DIMaslov1904/sup5th](https://github.com/DIMaslov1904/sup5th). В Firefox manifest включён постоянный `update_url`: `https://raw.githubusercontent.com/DIMaslov1904/sup5th/main/updates/firefox.json`. В канал автообновлений попадают только стабильные подписанные XPI; релизы Chrome обновляют собственный справочный JSON и не меняют канал Firefox. Порядок именования пакетов и выпуска описан в публичном репозитории.

Цель первого этапа — Firefox Desktop 140+. Фон работает как непостоянная страница Manifest V3.

Firefox не поддерживает ограничение `storage.local.setAccessLevel`. Поэтому данные, настройки и доступы сохраняются в IndexedDB страниц расширения (`sup5th-private-data`); в `storage.local` записываются только метки изменений для обновления интерфейса. Ключ разблокировки и состояние сессии остаются в доверенном `storage.session`. Content scripts получают данные только через разрешённые сообщения.

Биометрическая защита в Firefox открывается на отдельной странице расширения. Включение и разблокировка требуют нажатия кнопки на этой странице; закрытие popup не прерывает операцию. Копирование, автологин или загрузка доступов продолжаются после успешной разблокировки. Страница привязана к одноразовому запросу и вкладке на пять минут; закрытие вкладки или отмена не разблокируют хранилище. Состояние запроса содержит только ссылки на записи, без паролей и ключей. Для копирования после проверки устройства используется разрешение `clipboardWrite`. Сценарий Firefox пока экспериментальный: выбор RP ID по адресу расширения не проходит реальную проверку браузера (`The operation is insecure`); требуется отдельное исправление с поддерживаемым RP ID. Проверки с имитацией WebAuthn этот запрет не обнаружили. Chrome сохраняет прежний RP ID и сценарий внутри popup.

В Firefox manifest заявлены передача данных авторизации (`authenticationInfo`) при входе и адресов сайтов (`browsingActivity`) при сетевых проверках и загрузке счётчиков/иконок.

## Неочевидные функции интерфейса

- Поиск понимает Unicode/Punycode и варианты раскладки; ссылки сохраняют рабочие URL.
- Вставка в поиск удаляет нецифровые символы и открывает тикет, если осталось 6–8 цифр. В остальных случаях работает обычный поиск. В модальном окне тикета длина номера не ограничена.

## API и формат данных

Адреса Apps Script задаются в настройках. Доступ к Google API проверяет Google; запросы API выполняются с cookies.

API проектов возвращает массив в `result` (либо корневой массив). Строка проекта:

```json
{
  "result": [
    [
      "название",
      "URL сайта",
      "инструкция",
      "URL админки",
      "CMS",
      "ключ создания тикета",
      "Git"
    ],
    ...
  ]
}
```

API доступов:

```json
{
  "result": {
    "access": [
      [
        "Проект",
        "https://example.org",
        "login",
        "password",
        "ftp.example.org",
        "ftp-user",
        "ftp-password"
      ],
      ...
    ],
    "services": [
      [
        "Сервис",
        "https://service.example.org",
        "login",
        "password"
      ],
      ...
    ]
  }
}
```

Сохранены нормализация пробелов и несколько логинов/паролей в одной ячейке через перевод строки. Позиции логинов и паролей должны совпадать.

Расширение присваивает записям локальные UUID.

## Защита доступов

Включается пользователем. Используется passkey/WebAuthn с обязательной проверкой пользователя. Windows сохраняет платформенный сценарий Windows Hello и PRF. На macOS выбор провайдера предоставляется браузеру. Если доступен PRF, ключ шифрования выводится из PRF-секрета. Для iCloud Keychain («Пароли», macOS 15+) в окне создания ключа можно выбрать «Другой способ» → «Связка ключей iCloud». Также доступен Google Password Manager с поддержкой PRF.

При настройке на Mac провайдера без PRF автоматически включается локальный режим совместимости. В нём ключ обёртки выводится через HKDF-SHA-256 из credential ID с отдельной меткой и случайной солью. В расширении сохраняются только SHA-256-хеш идентификатора, соль, имя ключа и зашифрованный ключ хранилища. Сам credential ID не передаётся в background и не записывается в storage. Разблокировка использует discoverable `get()` с пустым `allowCredentials`, проверяет хеш выбранного ключа и флаги UP/UV ответа. Локальная регистрация требует resident key; в имени ключа есть короткий код для выбора среди старых passkey.

Режим совместимости согласован как дополнительный слой защиты: credential ID не имеет гарантий секретности PRF. Собственный сервер, сетевые запросы и отдельное приложение для этого режима не нужны.

На Mac если поддержка PRF подтверждена или ответ не содержит этого признака, секрет сначала запрашивается через отдельный `get()`; отсутствие секрета позволяет выбрать режим совместимости. Для совместимости с Windows Hello сохранён прежний переход `create()` → `get()` без перехода на credential ID.

Пароли и FTP-секреты шифруются AES-GCM. Логины, адреса и признаки наличия доступа остаются открытыми. Разблокированный ключ находится только в `storage.session`.

Автоблокировка срабатывает при 10 минутах без пользовательского ввода на устройстве через `chrome.idle`, блокировке экрана и завершении браузерной сессии. Это системная активность, а не активность только popup. Блокировка аннулирует ожидающий автологин. Ожидающие сессии авторизации содержат ссылки на записи, а не пароли.

`storage.local` и `storage.session` доступны только доверенным страницам расширения. Привилегированные сообщения проверяют отправителя. Content scripts получают только данные для явно начатой операции.

Потеря passkey требует повторного подключения данных. Отключение защиты после разблокировки возвращает локальное открытое хранение паролей.

## Разрешения

Расширение имеет постоянный доступ ко всем HTTP/HTTPS-сайтам через `host_permissions`. Дополнительных запросов разрешения для отдельных доменов нет. Каталог проектов не зашит в manifest.

- SEO подключается программно через `activeTab` после открытия расширения пользователем.
- При автологине скрипт заполняет только вкладку, открытую этой операцией. Если хранилище заблокировано, сначала требуется биометрия.
- Проверка ссылок, загрузка иконок и источников sitemap используют постоянные разрешения на HTTP/HTTPS.
- Доступы можно отозвать в настройках Chrome. Без разрешения сетевая проверка показывает неопределённый результат.

## SEO

При открытии SEO автоматически восстанавливается результат текущего документа либо начинается анализ с preloader. Отчёт привязан к вкладке и документу; после закрытия popup сохраняется на одну минуту в рамках сессии браузера.

Объединяются применимые meta robots, показываются ограничения для Googlebot и Yandex. robots.txt сопоставляется с нормализацией Unicode и percent-encoding. Ошибка получения правил даёт неизвестный результат. Отсутствие noindex не гарантирует индексацию.

HTTP-проверки выполняются без cookies. Различаются подтверждённые 404/410, необходимость авторизации, ограничение проверки, ошибка сервера, таймаут и неопределённая сетевая ошибка. Отчёт указывает размер выборки; дубли проверяются только среди полученных метаданных.

Sitemap: вложенные индексы, gzip, объединение и дедупликация. Защитные ограничения сетевого анализа: 200 файлов, 50 000 URL, до 8 МБ распакованного текста одного файла. Неполный результат обозначается явно и экспортируется как `sitemap-partial.xml`.

Тяжёлый SEO-отчёт сохраняется при новом сканировании; изменения фильтров и навигации передают небольшой патч состояния с объединением частых обновлений.

## Структура

```text
src/background/
  service-worker.js       события и маршрутизация сообщений
  storageRepository.js    схема, очередь записи, поколение данных
  apiSettings.js          открытые адреса API
  apiRefresh.js           запросы, обновление и фоновые задания
  catalogueData.js        нормализация и индексированный каталог
  recordIdentity.js       локальные UUID
  credentialVault.js      шифрование и системная автоблокировка
  projectAccess.js        доступы и сессии автологина
  actionBadge.js          индикатор проекта
src/content-script/       формы, SEO и интеграция саппорта
src/popup/                интерфейс, фоновые состояния, настройки и инструменты
src/options/              инструкция, подробный аудит и sitemap
src/biometric/            отдельная страница WebAuthn для Firefox
src/icons/                IndexedDB, очередь и обработка favicon
src/utils/                адреса, SEO-правила, WebAuthn и генератор паролей
```

Стек: Vue 3, Vite 8, Tailwind CSS 4, CRXJS. Постоянными данными управляет worker; popup подписывается на изменения хранилищ и использует небольшой общий реактивный модуль состояний.
