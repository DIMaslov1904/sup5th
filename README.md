# SUP 5th

Chrome Manifest V3: каталог проектов и доступов, заполнение форм авторизации, SEO страницы, аудит ссылок, объединение sitemap и локальные инструменты.

## Запуск

Нужен актуальный Node.js, совместимый с Vite 8. Расширение рассчитано на Chrome 130+.

```bash
npm ci
npm run dev
npm run build
```

Для установки распакованной сборки откройте `chrome://extensions`, включите режим разработчика и выберите `dist`. ZIP с версией из manifest создаётся в `dist-zip`.

## Интерфейс

Popup: 520 × 600 px. Шапка содержит текущий сайт, SEO, инструменты, поиск, переход к тикету, состояние защиты и настройки.

- Поиск открывает каталог при клике, вводе текста или Enter. Переход через Tab не меняет страницу.
- Карточки каталога открываются мышью, Enter или пробелом. Ссылка справа открывает сайт отдельно.
- Поиск понимает Unicode/Punycode и варианты раскладки; ссылки сохраняют рабочие URL.
- Настройки разделены на подключение, загрузку, защиту и обслуживание.
- Состояние фоновой загрузки видно после закрытия и повторного открытия popup. В настройках показаны даты успешной загрузки и актуальность данных.

## API и формат данных

Адреса Apps Script задаются в настройках и хранятся локально открыто. Доступ к Google API проверяет Google; запросы API выполняются с cookies. Инструкция и код Apps Script доступны на странице инструментов расширения.

API проектов возвращает массив в `result` (либо корневой массив). Строка проекта:

```text
[название, URL сайта, инструкция, URL админки, CMS, ключ создания тикета, Git]
```

API доступов:

```json
{
  "result": {
    "access": [["Проект", "https://example.org", "login", "password", "ftp.example.org", "ftp-user", "ftp-password"]],
    "services": [["Сервис", "https://service.example.org", "login", "password"]]
  }
}
```

Сохранены нормализация пробелов и несколько логинов/паролей в одной ячейке через перевод строки. Позиции логинов и паролей должны совпадать. FTP/SSH-доступ строки сохраняется один раз независимо от числа аккаунтов сайта. API доступов заменяет целиком обе коллекции после успешной проверки ответа.

Расширение присваивает записям локальные UUID. Перестановка строк не меняет ID уникального доступа. При неоднозначных дублях ID сохраняется только при точном сопоставлении; изменившийся доступ потребует обновления карточки. Действия не используют индексы строк.

Исходный URL сайта сохраняется для переходов. Ключ сопоставления учитывает хост и порт; при поиске проекта приоритет имеет точный хост, затем ближайший родитель с тем же портом.

## Данные и фоновые операции

Поддерживается только текущая схема `schemaVersion: 1`, без миграций старых форматов. При первом запуске этой схемы несовместимые локальные настройки, доступы и состояние защиты сбрасываются. Потребуется повторно указать API, загрузить данные и при необходимости включить биометрию.

Записи в хранилище согласуются общей очередью. Сброс отменяет текущую загрузку и меняет поколение данных: старый ответ не может записать данные обратно. У фоновой загрузки есть состояние, прогресс и результат в `storage.session`. После перезапуска worker незавершённая операция помечается прерванной.

Плановое обновление — раз в неделю. Проекты могут обновляться при заблокированном хранилище; для обновления зашифрованных доступов требуется разблокировка. Сетевая ошибка одного источника не уничтожает успешный кеш другого.

## Защита доступов

Включается пользователем. Собственный PIN расширения удалён. Используется платформенный passkey/WebAuthn PRF; текущий целевой сценарий — Windows Hello. Проверка устройства может допускать системный PIN Windows: WebAuthn не гарантирует конкретный способ проверки пользователя. Поддержка macOS требует отдельной проверки совместимости.

Пароли и FTP-секреты шифруются AES-GCM. Логины, адреса и признаки наличия доступа остаются открытыми. Разблокированный ключ находится только в `storage.session`.

Автоблокировка срабатывает при 10 минутах без пользовательского ввода на устройстве через `chrome.idle`, блокировке экрана и завершении браузерной сессии. Это системная активность, а не активность только popup. Блокировка аннулирует ожидающий автологин. Ожидающие сессии авторизации содержат ссылки на записи, а не пароли.

`storage.local` и `storage.session` доступны только доверенным страницам расширения. Привилегированные сообщения проверяют отправителя. Content scripts получают только данные для явно начатой операции.

Потеря passkey требует повторного подключения данных. Отключение защиты после разблокировки возвращает локальное открытое хранение паролей.

## Разрешения

Постоянный доступ: Apps Script, Googleusercontent, Google Accounts и `support.5th.ru`. Каталог проектов не зашит в manifest.

- SEO подключается программно через `activeTab` после открытия расширения пользователем.
- При автологине запрашивается доступ к домену админки; скрипт заполняет только вкладку, открытую этой операцией.
- Проверка ссылок и загрузка иконок запрашивают необходимые домены по явному действию пользователя.
- Дополнительный источник sitemap может потребовать отдельного разрешения. Повторная загрузка запрашивает домены файлов, завершившихся ошибкой.
- Доступы можно отозвать в настройках Chrome. Без разрешения сетевая проверка показывает неопределённый результат.

Разрешения Chrome выдаются на хост; Chrome не ограничивает их отдельным TCP-портом. Сопоставление доступов внутри расширения порты различает.

## Автозаполнение

Выбирается видимая форма с паролем текущего аккаунта и подходящим логином: `autocomplete=username`, имя поля, email или соседнее текстовое поле. Скрытые, отключённые поля и формы смены пароля пропускаются. Кнопка отправки ищется только внутри выбранной формы; Tilda заполняется без автоматической отправки.

Нестандартная форма, двухэтапный вход на разных страницах, Shadow DOM, CAPTCHA и MFA могут требовать ручных действий. Для конкретных исключений можно добавлять адаптеры, сохраняя общий выбор формы.

## SEO

При открытии SEO автоматически восстанавливается результат текущего документа либо начинается анализ с preloader. Кнопка «Обновить» находится внизу панели. Отчёт привязан к вкладке и документу; после закрытия popup сохраняется на одну минуту в рамках сессии браузера.

Base в сводке: объявленный адрес либо корень сайта с пометкой «не задан». Относительные ссылки разрешаются по фактическому `document.baseURI`, согласно поведению браузера.

Объединяются применимые meta robots, показываются ограничения для Googlebot и Yandex. robots.txt сопоставляется с нормализацией Unicode и percent-encoding. Ошибка получения правил даёт неизвестный результат. Отсутствие noindex не гарантирует индексацию.

HTTP-проверки выполняются без cookies. Различаются подтверждённые 404/410, необходимость авторизации, ограничение проверки, ошибка сервера, таймаут и неопределённая сетевая ошибка. Отчёт указывает размер выборки; дубли проверяются только среди полученных метаданных. Процент аудита — доля технических проверок, не прогноз поисковых позиций.

Sitemap: вложенные индексы, gzip, объединение и дедупликация. Защитные ограничения сетевого анализа: 200 файлов, 50 000 URL, до 8 МБ распакованного текста одного файла. Неполный результат обозначается явно и экспортируется как `sitemap-partial.xml`.

Тяжёлый SEO-отчёт сохраняется при новом сканировании; изменения фильтров и навигации передают небольшой патч состояния с объединением частых обновлений.

## Иконки и инструменты

Иконки хранятся в IndexedDB по origin. Запросы идут последовательно с интервалом 2,5 секунды; состояние очереди переживает остановку worker. SVG используется как изображение; растровые иконки уменьшаются до PNG 64 × 64.

Жёсткого лимита общего кеша нет. При превышении 50 МБ в настройках один раз показывается предупреждение; загрузка продолжается. Технические ограничения входного изображения и таймауты сохраняются. Действует квота браузерного хранилища.

Генератор паролей использует `crypto.getRandomValues` и выбор без modulo bias. Настраиваются длина, строчные/прописные буквы, цифры, спецсимволы, латиница/кириллица/смешанный алфавит. Можно включить разделители: `-` и `_` выбираются случайно и располагаются в случайных местах. Длина включает разделители; каждая включённая группа присутствует. Пароль не сохраняется и не отправляется в сеть.

## Структура

```text
src/background/
  service-worker.js       события и маршрутизация сообщений
  storageRepository.js    схема, очередь записи, поколение данных
  apiSettings.js          открытые адреса API
  apiRefresh.js           запросы, обновление и фоновые задания
  catalogueData.js        нормализация и индексированный каталог
  recordIdentity.js       локальные UUID
  credentialVault.js      шифрование и системная автоблокировка
  projectAccess.js        доступы и сессии автологина
  actionBadge.js          индикатор проекта
src/content-script/       формы, SEO и интеграция саппорта
src/popup/                интерфейс, фоновые состояния, настройки и инструменты
src/options/              инструкция, подробный аудит и sitemap
src/icons/                IndexedDB, очередь и обработка favicon
src/utils/                адреса, SEO-правила, WebAuthn и генератор паролей
```

Стек: Vue 3, Vite 8, Tailwind CSS 4, CRXJS. Pinia не используется: постоянными данными управляет worker; popup подписывается на изменения хранилищ и использует небольшой общий реактивный модуль состояний.

UI-компоненты находятся в `src/popup/components/ui`, цвета и размеры — в `src/styles/main.css`. Новые страницы должны использовать эти компоненты и токены.
